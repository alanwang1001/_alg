# 旅行推銷員問題 (TSP) 優化策略總結

在旅行推銷員問題中，我們面臨的是一個 NP-Hard 等級的組合最佳化挑戰。

## 🎯 我們優化了什麼？ (優化目標)

我們的核心優化目標非常單純：**在給定的一組城市中，找出「總移動距離最短」且「每個城市只經過一次並回到起點」的合法路徑。**
實務上，由於窮舉所有路徑的時間成本太高 ($O(N!)$)，我們實際上是在「運算時間」與「路徑最短化」之間取得最佳平衡，將一個極差的「隨機初始路徑」一步步優化為「近似最佳解」。

---

## 🛠️ 我們是怎麼做的？ (五大優化手段)

以下是針對 TSP 實作的五種優化演算法，每一種都有其獨特的優化切入點：

### 1. 改良法 (2-opt Algorithm)
* **優化的痛點**：路徑中出現的「交叉點」（走冤枉路）。
* **怎麼做的**：
  演算法會遍歷當前路徑，任選兩條不相鄰的邊。如果這兩條邊發生交叉，2-opt 會將這兩條邊打斷，並將中間的路徑「反轉 (Reverse)」後重新連接。這個動作會持續進行，直到路徑中沒有任何交叉點為止。這是一種**局部極值 (Local Optimum)** 的優化方式。

### 2. 爬山演算法 (Hill Climbing)
* **優化的痛點**：相鄰狀態中是否存在更好的微調空間。
* **怎麼做的**：
  這是一種「貪婪的局部搜尋」。我們定義每一次的探索動作為「隨機交換兩個城市的位置」。系統會評估所有可能的交換，並**只往距離變短的方向走**。一旦發現任何交換都無法讓距離變短，優化就會停止。缺點是極容易卡在局部最佳解的「山谷」裡出不來。

### 3. 模擬退火法 (Simulated Annealing)
* **優化的痛點**：爬山演算法容易卡在局部最佳解（Local Minima）的致命傷。
* **怎麼做的**：
  引入物理學中金屬降溫的機制。在優化過程中（隨機交換兩城市），如果路徑變短，我們直接接受；**如果路徑變長，我們依然會以一個機率 $P$ 接受這個較差的解**。
  這個機率 $P$ 與當前的「溫度」有關：高溫時（初期），系統有極高機率接受差的解，藉此「跳出」局部低谷；隨著迭代進行，溫度逐漸下降（降溫），系統越來越挑剔，最終轉變為類似爬山演算法的嚴格收斂。

### 4. 梯度下降法 (Hopfield Neural Network)
* **優化的痛點**：嘗試用連續空間的微積分工具來解決離散的排序問題。
* **怎麼做的**：
  這是一種將問題「降維打擊 / 轉換維度」的做法。TSP 本身不能微分，所以我們建立一個神經網路矩陣，設計一個「能量函數 (Energy Function)」，將「總距離」與「違反遊戲規則（如走訪同一城市兩次）」視為懲罰項。
  接著對這個能量函數求偏微分，利用梯度下降讓神經元的狀態網格逐漸穩定，最後再將連續的機率值二值化（轉為 0 與 1），還原成離散的城市路徑。

### 5. 貪婪演算法 (Nearest Neighbor)
* **優化的痛點**：如何在極短的時間內，無中生有生出一個「還算合理」的初始解。
* **怎麼做的**：
  目光短淺的極致。從隨機一個起點出發，每一步只看眼前：**「誰離我最近且還沒去過，我就去哪裡」**。這種做法捨棄了全局視野（Global View），優點是速度極快 $O(N^2)$，缺點是走到最後往往只剩下極遠的城市，導致收尾階段距離暴增。

---

## 💡 終極優化：實戰組合技 (Hybrid Approach)

單一演算法往往有其極限。在我們提供的程式碼中，真正最強的優化是**「貪婪法 + 改良法 (2-opt)」**的組合：

1. **第一階段 (粗調 - 貪婪法)**：先用時間複雜度極低的「貪婪演算法」，瞬間產生一條品質中等、但絕對比隨機亂走好很多的初始路徑。
2. **第二階段 (微調 - 2-opt)**：針對貪婪演算法結尾經常產生的「大交叉」與繞路，使用 2-opt 進行局部反轉優化，把交叉點全部解開。

**優化結果總結**：這種組合技利用貪婪法省下了大量的隨機探索時間，再利用 2-opt 彌補了貪婪法目光短淺的缺陷，是實務上 CP 值（性價比）最高的 TSP 優化策略。
