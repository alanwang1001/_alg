# 習題 1：計算 $2^n$ 的演算法效能比較

本專案實作並測試了四種不同的方式來計算 $2^n$（以 $n = 100$ 為基準），分析其運算效率、資源消耗以及在極限狀況下的表現。

---

## 一、演算法實作說明

### 1. 方法 1：內建運算子 (`2 ** n`)
- **實作方式**：直接呼叫 Python 內建的次方運算子 `**`。
- **時間複雜度**：$O(\log n)$（底層採用二元快速冪 Binary Exponentiation，並由 C 語言優化）。
- **空間複雜度**：$O(1)$（除了儲存大數結果所需的空間之外，無額外呼叫堆疊開銷）。

### 2. 方法 2a：雙遞迴加法 (`power2n(n-1) + power2n(n-1)`)
- **實作方式**：利用 $2^n = 2^{n-1} + 2^{n-1}$，每次呼叫自身兩次。
- **時間複雜度**：$O(2^n)$（指數時間，狀態樹呈滿二元樹展開）。
- **空間複雜度**：$O(n)$（呼叫堆疊最大深度為 $n$）。

### 3. 方法 2b：單遞迴乘法 (`2 * power2n(n-1)`)
- **實作方式**：利用 $2^n = 2 \times 2^{n-1}$，每次僅呼叫自身一次。
- **時間複雜度**：$O(n)$（線性時間，共呼叫 $n$ 次遞迴）。
- **空間複雜度**：$O(n)$（呼叫堆疊深度為 $n$）。

### 4. 方法 3：遞迴 + 查表 (`Memoization`)
- **實作方式**：結構與方法 2a 相同，但使用字典（Dictionary）快取已計算的子問題結果。當遇到相同的子問題時，直接從表中回傳，避免重複計算。
- **時間複雜度**：$O(n)$（子問題總數僅 $n+1$ 個，每個子問題只被實質計算一次）。
- **空間複雜度**：$O(n)$（遞迴呼叫堆疊深度為 $n$，快取字典需要 $O(n)$ 的儲存空間）。

---

## 二、測試結果與比較 ($n = 100$)

| 方法 | 演算法特性 | 時間複雜度 | 預估 / 實測時間 | 執行結果 |
| :--- | :--- | :--- | :--- | :--- |
| **方法 1** (`2**n`) | 內建快速冪 (C 實作) | $O(\log n)$ | $< 0.00001$ 秒 | **最快**，瞬間產出結果 |
| **方法 2a** (雙遞迴) | 樹狀重複計算 | $O(2^n)$ | **出不來**（約 $10^{13}$ 年） | **無法產出**（算力耗盡卡死） |
| **方法 2b** (單遞迴) | 線性鏈狀遞迴 | $O(n)$ | $\approx 0.00003$ 秒 | **快**，成功產出結果 |
| **方法 3** (查表遞迴) | 動態規劃記憶化 | $O(n)$ | $\approx 0.00008$ 秒 | **快**，成功產出結果 |

---

## 三、關鍵問題解答

### 1. 哪個最快？
- **方法 1** 最快。底層由 Python CPython 核心直接以 C 語言進行二元快速冪運算，無需經過 Python 層級的函式呼叫與堆疊處理，開銷極低。

### 2. 哪個慢？
- 在可以正常執行完成的方法中（方法 1、2b、3），**方法 3** 相較於方法 2b 稍微慢了一點點。
  - 原因：方法 3 仍有兩次函式呼叫（即使第二次直接查表命中）以及字典雜湊尋址的額外開銷；而方法 2b 純粹只做單次呼叫與整數乘法。
  - 不過方法 2b 與方法 3 都是毫秒級別（$O(n)$），肉眼感受差異不大。

### 3. 哪個出不來？為什麼？
- **方法 2a 完全出不來**。
  - 當 $n = 100$ 時，運算次數為：
    $$2^{100} \approx 1.26765 \times 10^{30} \text{ 次}$$
  - 即使超級電腦每秒能執行 $10^{10}$ 次運算，也需要超過 $4 \times 10^{12}$ 年（數兆年）才能完成。
  - 若在一般電腦上直接執行 `power2n_2a(100)`，程式將陷入實質上的永久凍結，因此程式內設有安全機制提前跳過。
