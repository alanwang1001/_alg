# Week 9 作業：用「搜尋法」解決五個經典問題

陳鍾誠《演算法》115 學年下學期，搜尋法習題實作。
搜尋法 (Search) 的共同心法，是把問題化成一張狀態圖 State Graph：
起點 --[動作/開展]--> 新狀態 --[動作/開展]--> ... --> 目標狀態

只要定義清楚「狀態是什麼、動作有哪些、目標怎麼判斷」， 程式就完成了 80%；剩下的差別只在「用什麼策略決定下一次展開哪個狀態」。 本作業五題分別用了 DFS、BFS、DFS+剪枝（回溯法）、A*，以及三種 IC 繞線搜尋法。

## 搜尋策略總覽

| 策略 | 開展順序 | 保證最短？ | 適用情境 |
|---|---|---|---|
| DFS | 沿一條支路走到底（遞迴/堆疊） | 否 | 迷宮、可解性判定（找得到就行） |
| 回溯法 | DFS + 死路退一步 + 剪枝 | 是（解的完整與正確性） | 八皇后、組合問題 |
| BFS | 一層一層（FIFO 佇列） | 是（等權重圖上） | 過河、最少步數 |
| A* | 挑 f(n)=g(n)+h(n) 最小者 | 是（h 不高估時） | 遊戲尋路、地圖導航 |
| Lee 演算法 | BFS 水波 | 是 | IC 繞線 |
| Hadlock 演算法 | 0/1 BFS（依 detour 排序） | 是 | IC 繞線（更快） |

## 1. 老鼠走迷宮（DFS）
- **狀態**：座標 (y, x)；起點：S；目標：E
- **動作**：上下左右各走一步（不能穿 #）
- **目標判斷**：走到 E 即結束
- **機制**：visited 讓同一格不走第二次，否則會繞圈圈。path 記錄當前路徑堆疊，深入時 push、死路時 pop（回溯 backtracking）。DFS 只保證找得到路徑，不保證最短。

## 2. 狼羊甘藍菜過河（BFS）
- **狀態**：(農夫, 狼, 羊, 菜) 各為 0=左岸、1=右岸，共 2⁴=16 個狀態。
- **約束**：農夫不在場時，羊不能和狼同岸、羊不能和菜同岸。
- **機制**：用 FIFO 佇列存放路徑。層層擴散，依「層數」對映「步數」，第一次彈出目標時絕對是最短解徑（7步）。

## 3. 八皇后（DFS + 剪枝 = 回溯法）
- **狀態**：`queens[r] = c`（第 r 列皇后放在第 c 行）。
- **約束**：同行 (`queens[i] == col`) / 對角線 (`abs(i - row) == abs(queens[i] - col)`) 不能有兩個皇后。
- **機制**：不剪枝有 8⁸ ≈ 1677 萬種可能；有剪枝（放下去會被打的分支直接不遞迴）大幅縮減搜索樹，找出全數 92 組解。

## 4. NPC 搜尋玩家（A*）
- **機制**：替每個待開展的格子算綜合評分 `f(n) = g(n) + h(n)`。`g(n)` 是起點實際成本，`h(n)` 是曼哈頓距離估算剩餘成本。
- **優勢**：用 priority queue (heapq) 挑 f 最小者開展。保守估計下保證最短路，且實測開展格數遠少於 BFS。

## 5. IC 電路繞線（Lee / Hadlock / A*）
- **問題**：迷宮尋路加逐條繪製的工業版，多條 net 繞線且不可重疊。
- **對比分析**：
  - **Lee (BFS)**：保證最短，擴展如水波紋。
  - **Hadlock (0/1 BFS)**：依 detour（偏離目標方向）計數，只往反向加 1，速度快於 Lee。
  - **A***：加入曼哈頓啟發函數。三者皆得最短線路，僅試錯成本與開展格數不同。

### 五題共同的收穫
1. 先把問題翻譯成（狀態、動作、目標）三元組——解法自然浮現。
2. 要求的答案不同，策略就不同：有解就行（DFS）；要最短步（BFS / A*）；要全部解（回溯法）。
3. 剪枝與啟發函數是效率的分水嶺：好的約束檢查與好的 h 能省下十倍以上的搜尋。
4. 這五個程式都是同一套樣板：frontier + visited + parent，差別只在 frontier 用 stack、queue 還是 heap。
